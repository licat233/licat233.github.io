01 / The idea

Not another chatbot. An AI operating layer for the company.

EAO does not try to replace mature RAG engines, Agent frameworks, web clients or business systems. It connects them through a reproducible enterprise architecture with clear authority, knowledge and execution boundaries.

02 / Capabilities

A small set of capabilities that form a complete office.

01

Department AI

Specialized Hermes Profiles give departments distinct assistants, tools, knowledge scope and least-privilege execution boundaries.

02

Enterprise Knowledge

WeKnora Document/RAG grounds factual retrieval; Native Wiki holds reusable synthesized business knowledge.

03

Work History

EAO Ledger records bounded event, work and content history without turning general memory into a second source of truth.

04

Company Files

Catalog-first Enterprise Archive discovers external files efficiently while authorized query-time reading preserves access boundaries.

05

Agentic Execution

Hermes Agent connects assistants to approved tools and actions, with bounded execution visibility instead of exposing hidden chain-of-thought.

06

Operational Governance

Control Plane, Boundary Principles, health checks, upgrades, rollback, recovery and acceptance evidence keep the system maintainable.

03 / Architecture

Upstream first. Thin integration. Clear ownership.

EAO deliberately builds around mature projects instead of forking them. The project owns system design, deployment contracts, governance boundaries and the thin adapters needed to make the stack operate as one enterprise system.

04 / Design principles
Use the lightest sufficient execution path. Complexity must earn its place.

Human identity ≠ Agent identity

People, Agent Profiles and provider credentials remain separate authority domains.

Knowledge ≠ Memory ≠ History

RAG, Wiki, Ledger, Archive and optional Agent memory have different jobs and sources of truth.

Capability before infrastructure

Reuse upstream capability first; add custom infrastructure only when a real gap remains.

Simple work stays simple

Kanban and multi-Agent delegation are fallback capabilities, not mandatory ceremony for every task.

Changes remain bounded

Workspace, task, Agent, change and authority boundaries constrain blast radius without adding a heavy workflow engine.

Production is evidence

Health, recovery, access and acceptance checks distinguish a working demo from an operable enterprise deployment.

05 / Reference implementation

Built from a real deployment, designed to be reusable.

ARMOR is the first reference implementation. Company-specific configuration and lessons stay separated from the generic EAO blueprint so another organization can reproduce the architecture without inheriting ARMOR's private configuration.
