01 / 核心思路

记忆系统不应该制造生命周期官僚流程。

这套架构希望路由足够确定，同时避免把“Active → Completed 搬文件”“重复确认已经授权的决定”等工作长期甩给人类。

01

稳定路由

由对象类型决定位置；目录表达的是运营用途，而不是生命周期状态。

02

Skill 与存储分离

Skill 控制行为和路由，Vault 保存持久业务记忆；派生工具不能变成第二个权威数据源。

03

降低人类成本

确定性的路由、元数据维护和例行操作尽量由 Agent 完成，把人的注意力留给真实的歧义、权限与风险判断。

02 / 架构层次

尽量少的明确层。

仓库保存的是架构、Router、测试和维护工具，本身并不保存实时业务记忆。

Shared Skill定义多个 Agent 共用的记忆行为和路由纪律。
Router当持久写入的目的地尚不明确时，先确定一个可重复、确定性的路径。
知识质量只读检查 authority、provenance 与可能的重复标题问题。
Vault持久业务记忆存储，与代码、架构和诊断工具保持分离。

03 / 工程经验

不要把“记忆”做成第二套操作系统。

项目后期主动移除了迁移专用工具和过时架构副本，让 Git 历史承担历史记录，而不是让旧规则继续和当前规则并排存在。

项目位置生命周期中立

具名项目长期留在同一个稳定位置；Draft、Review、Published、Retired 等状态，不要求源文件不断搬目录。

显式维护

正常记忆任务不自动检查仓库版本，也不静默自更新。架构升级由操作者明确发起。

当前状态

armor-memory 现在更适合作为 EAO 早期阶段的一份独立工程记录来理解。当前 EAO 的企业知识架构已经演进，不再把 armor-memory / armor-vault 作为权威知识层；这个仓库主要保留了当时对路由、权威来源和人类操作成本等问题的工程探索。
