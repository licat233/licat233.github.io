This Blog runs on **Astro + GitHub Pages**. I write in Markdown without using a separate CMS. Astro builds static HTML from the repository's Markdown files, and GitHub Actions deploys the output.

## Where do posts live?

Markdown posts live in the repository's root `_posts/` directory. **Astro reads them through a Content Collection** to generate blog pages.

For a Chinese post, create a file such as:

```text
_posts/2026-10-28-my-first-note.md
```

A minimal post looks like this:

```yaml
---
title: "我的第一篇笔记"
date: 2026-10-28
lang: zh
description: "简要介绍这篇文章要解决的问题。"
---

Markdown content begins here.

## A heading

Lists, tables, links, images, and code blocks are supported.
```

The key frontmatter fields are `title`, `date`, and `lang`; `description` is recommended. This site accepts `zh` and `en` language values.

New posts do not need a `layout` field. In this project, the URL comes from the Astro route and filename, not the `permalink` frontmatter field.

The Content Collection is configured in `astro/src/content.config.ts`. The Chinese route is generated by `astro/src/pages/blog/[slug].astro`. The filename's date prefix is stripped when creating the URL:

```text
/blog/my-first-note/
```

Keep slugs readable and unique. Renaming a published Markdown file can change its URL.

## How do I publish an English translation?

Create a separate Markdown file in the same directory, using the `-en.md` suffix:

```text
_posts/2026-10-28-my-first-note-en.md
```

For example:

```yaml
---
title: "My First Note"
date: 2026-10-28
lang: en
description: "A short summary of this article."
translation_url: /blog/my-first-note/
---

The English Markdown article starts here.
```

This becomes `/en/blog/my-first-note/`. Once **both language versions are published**, add this to the Chinese post's frontmatter:

```yaml
translation_url: /en/blog/my-first-note/
```

Only link to an actual translated post. If a translation has not been published, omit `translation_url`. The site's language switch will then lead to the other language's blog index instead of advertising a nonexistent translated article.

Translate and review the whole article, not just its title.

## How does Markdown become a page?

The build pipeline is:

```text
_posts/*.md
   ↓ Astro Content Collection (filtered by lang)
   ↓ /blog/[slug]/ and /en/blog/[slug]/ static pages
   ↓ GitHub Actions: build, checks, and deploy
   ↓ GitHub Pages
```

Both Blog indexes use the same content collection. There is no need to create a new `.astro` file or edit the navigation for each post.

Markdown may reference a site asset such as `/assets/example.png`; ensure the image actually exists and is deployed. Check image paths and internal links in both languages.

## How do I check and publish a post?

From the repository root:

```bash
cd astro
npm ci
npm run build
npm run check
node scripts/check-legacy-routes.mjs
```

The project uses Node.js 24 and a committed dependency lockfile. Install with `npm ci` on initial setup; you do not need to reinstall dependencies on every edit.

Prefer a working branch and Pull Request, then merge into `main` after the GitHub build and browser checks pass. The current `.github/workflows/deploy-astro-pages.yml` builds, verifies, and deploys the Astro site after changes to `main` (provided the repository variable `ASTRO_PAGES_ACTIVE` is enabled).

After deployment, open the article itself and the [English Blog index](/en/blog/). If you published a translation, verify the [Chinese Blog index](/blog/) and the language switch in both directions.

**In short: write Markdown → verify frontmatter and translation links → run checks → merge to `main` → verify the published pages.**
