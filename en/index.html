01 / About

Beyond “can it work?” — can it keep working?

Earlier work focused on Go, microservices, code generation, crawling and web tools; later it expanded into macOS automation and developer experience. Today, most of my effort goes into AI agents, knowledge systems and enterprise workflows.

I prefer lightweight engineering with clear boundaries and rollback paths. A project earns its place not only by being interesting, but by solving a real problem and reducing long-term maintenance cost.

04 / Method

How I prefer to build.

01 / USEFUL

Start with a real problem

Tools are not there to look advanced; they should reduce cost, mistakes, waiting or repetitive work.

02 / SMALLER

Prefer the lightest sufficient path

If one clear component solves it, don't add a second platform. Reuse mature capability before rebuilding it.

03 / DURABLE

Treat maintenance as product work

Deployment, upgrades, rollback, permissions, documentation and recovery are part of the product, not afterthoughts.
